# Cockpit 风格桌面更新设计

## 目标

Windows 版抖店助手复刻 Cockpit Tools 的更新体验：软件内展示版本、更新说明和下载进度；下载后由用户选择重启安装；失败时可打开 GitHub Release 手动下载。

## 范围

- 保持 Electron、React、NSIS 和 `electron-updater`，不迁移 Tauri。
- Windows x64；不改变已有业务页面或本地数据。
- 提供侧边栏更新动作、设置中的更新卡片和后台更新开关。
- 默认不后台下载；用户可在设置中开启。
- 不在业务任务进行中强制重启，始终由用户点击“重启更新”。

## 用户体验

1. 应用启动后和每隔一小时检查一次更新。
2. 左侧栏顶部显示紧凑更新动作：无更新时为“检查更新”，发现版本后为“更新 vX.Y.Z”，下载时显示百分比，下载完成后为“重启更新”。
3. 设置页的“软件更新”卡片显示当前版本、最新版本、更新说明和“检查更新”按钮。
4. 发现更新时打开应用内更新弹窗，用户可查看 Release 说明并选择“立即更新”或“稍后”。
5. 下载时弹窗显示实时进度、已下载大小和取消/关闭入口；完成后显示“稍后”和“重启更新”。
6. 检查或下载失败时弹窗保留错误状态，提供“重试”和“打开下载页”。
7. 若用户启用后台更新，应用仍先检查版本，但静默下载；准备完成后在侧边栏与右下角提示“重启更新”。
8. 更新后首次启动展示本版本更新说明一次。

## 实现边界

### Electron 主进程

扩展现有 `electron-updater` 封装为明确状态机：`idle`、`checking`、`available`、`downloading`、`ready`、`error`、`not-available`。订阅 `checking-for-update`、`update-available`、`update-not-available`、`download-progress`、`update-downloaded` 和 `error` 事件。

主进程通过受限 preload IPC 向页面公开：读取状态、手动检查、开始下载、重启安装、打开 Release 页和读取/保存后台更新偏好。渲染进程不能直接访问 Node 或 updater。

### React 页面

新增一个唯一的更新状态来源；侧边栏动作、设置卡片、更新弹窗和完成提示都读取它，避免多个入口出现不同进度。更新说明来自 GitHub Release；页面只渲染主进程已验证后的字段。

### 发布与更新源

更新器必须从公开、只存放安装包的 GitHub Release 获取 `latest.yml`、NSIS `.exe` 和 `.blockmap`。源码仓库即使为私有，也不作为客户端更新源。发布工作流先创建草稿 Release，所有 Windows 产物与元数据上传成功后才标记为 latest，避免用户下载到不完整版本。

每次发布递增 `package.json` 版本，创建相同的 `vX.Y.Z` 标签。GitHub Actions 构建、签名并发布；代码签名和发布 token 只使用 GitHub Secrets。

## 错误与安全

- 更新失败不影响软件启动或现有抽帧任务。
- 更新错误在界面显示通俗提示；技术细节只写本地日志，不显示 token、URL 参数或证书信息。
- 打包版才检查更新；开发版不联网检查。
- 发布仓库不得包含源码、用户数据、Cookie、数据库或签名凭据。
- 仅在下载完成且用户点击确认后调用 `quitAndInstall()`。

## 验证

- 单元测试覆盖每个 updater 状态转换、手动/后台模式、下载进度、错误重试和“重启安装”。
- React 测试覆盖侧边栏、设置卡片和弹窗的状态显示。
- 构建版本 `N` 安装在测试机后，发布版本 `N+1`：验证“检查 → 下载 → 重启安装 → 更新说明”。
- 在更新失败时验证“重试 / 打开下载页”可用且主窗口不退出。

## 外部前置条件

- 一个公开的 GitHub Release 仓库；只发布安装包和更新元数据。
- GitHub Actions Secrets：仅限发布仓库写入权限的 token、Windows 代码签名证书和证书密码。
- 首次仍需要手工安装带更新器的版本；之后才可软件内更新。
