# 全局执行记录设计

## 目标

让左侧“执行记录”成为所有任务的统一日志入口，同时保留各业务页面自己的当前执行面板和专属日志。

## 范围

左侧汇总以下大类：

- 涨粉券
- 商品优惠券
- 国补优惠券
- 新人礼金
- 看后搜
- 视频抽帧

各业务页面现有的当前执行区域不改动。

## 数据流

左侧页面通过一个统一的历史查询接口读取各业务已有的批次/任务数据，前端将不同数据结构映射为统一的日志条目。统一条目包含项目类型、批次名称或文件名、状态、任务总数、成功数、失败数、创建时间和子任务日志。失败原因直接显示已有的中文 `errorMessage`。

优惠券和新人礼金复用现有数据库批次表；看后搜和视频抽帧复用现有任务查询接口。没有历史数据的项目不生成空记录。

## 页面行为

左侧“执行记录”显示：

1. 顶部统计：今日执行、已完成、执行中、失败。
2. 按创建时间倒序排列的统一记录卡片。
3. 每张卡片明确显示项目标签，例如“涨粉券 / 新人礼金 / 看后搜”。
4. 卡片展开后显示该批次的每条子任务及中文状态、失败原因。
5. 点击“刷新记录”重新读取全部项目历史。

项目页面本身继续只展示自己的当前批次，不被全局列表替代。

## 错误处理

- 单个项目查询失败时，其他项目仍正常显示，并在页面顶部显示中文提示。
- 空历史显示“还没有执行记录”。
- 后端返回未知状态时统一显示“未知状态”，不丢弃记录。

## 验证

- 为统一映射函数添加单元测试，覆盖六类项目、成功/运行中/失败状态和中文错误原因。
- 为统一历史接口添加路由测试，确认所有项目记录都返回且按创建时间倒序。
- 运行全量测试和类型检查。
